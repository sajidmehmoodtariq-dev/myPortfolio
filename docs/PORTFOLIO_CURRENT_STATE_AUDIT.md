## 1. Executive summary

The strongest idea is the engineering exhibit itself. A carefully layered CSS assembly introduces the portfolio, a rail presents five projects, and a single orange trajectory leads into the contact endpoint. The limited colors, monospaced labels, and framed media tie those elements together. The site already has a deeper second layer through individual case studies and a source-linked PGC-DHA walkthrough.

The biggest gap is between the polish of the exhibit and the evidence visitors can inspect. Four projects are presented through designed diagrams. Nudge is the only featured project with a genuine application screenshot in this repository. Case studies link to pinned source, but generally lack approved ownership statements, dated releases, and measured outcomes. The CS50x credential is visible as a sentence in About. There is no artifact or verification link to substantiate it on the site.

The most productive next pass would put authentic work and the credential closer to the decisions visitors need to make. Preserve the hero and visual language. Give the work chapters distinct evidence, make project navigation predictable, and build one credential experience within About.

**Evidence convention.** “Browser” refers to an observation or test on the current local preview unless marked public or historical. “Source” describes code or content reviewed in this tree. “Unverified” means this audit did not exercise the behavior or independently confirm the underlying claim. Project implementation evidence below comes from the existing portfolio registry and its pinned links. This audit did not rerun each underlying product or validate its business outcomes.

- **Type.** Geist and Geist Mono are loaded through the local Geist package. Body line height is 1.6. The hero headline is `clamp(3rem, 5.2vw, 4.75rem)` at desktop, uses a 7.2vw slope below 64rem, and becomes `clamp(2.45rem, 10vw, 3.8rem)` below 40rem. Work intro ranges from 3.25 to 7.65rem and study titles from 3.15 to 8rem. Project headlines range from 2.5 to 4.7rem on desktop and 2.35 to 3.25rem on compact screens. Closing H2s use 2.75–6.5rem, with a separate contact treatment. Body and lead copy generally run 1–1.2rem. Index, tag, and register text frequently runs 0.62–0.75rem, with some hero screen microtype smaller still. The latter is ornamental but can visually resemble meaningful interface content.
- **Space and grid.** Standard container max is 76rem, hero and home header 84rem, gutters `clamp(1.25rem, 4vw, 3rem)`. Header variables are 4.25rem desktop and 3.8rem below 48rem. Work intro uses approximately 3.5–7.5rem top space, closing sections 3.75–7rem block space, and the contact content 4.3–9rem on wider layouts. Hero and media pairs, the project rail, the toolbox module grid, and the About text/timeline provide the layout grammar. Layout changes are driven primarily by 48rem and 64rem, with smaller type/media changes at 40rem and 25rem and height checks for sticky scenes.
- **Edges and surfaces.** The language is square and technical. Most containers use thin rules, 1px borders, and hard corners. Hero plates have 2px corners, while fasteners and contact points are circular. Radial washes, dark green gradients, low contrast grid textures, inset shadows, registration brackets, and occasional transparency create depth. Decorative shades are often local CSS literals rather than additional named tokens. Focus uses a 2px orange outline.
- **Objects and icons.** Arrows, callout leaders, crosshairs, and schematic lines use inline SVG, Unicode glyphs, or CSS. There is no icon library, Three.js, React Three Fiber, WebGL canvas, model file, texture map, or renderer-based lighting. The assembly uses CSS perspective, preserve-3d, displaced plates, gradients, translucency, and shading. Its camera is a transform on the DOM rig. Work figures use similar perspective and CSS planes. The architecture film contains its own baked lighting, labels, and orange curve.
- **Motion and transitions.** Hero entry is layered, the project rail moves horizontally, and the Toolbox/About/Contact chapters use modest type offsets and rules. The hero has separate rear/front/handoff paths. The desktop orbit is capped at 90rem and the page trajectory starts from the actual handoff bounds. A separate SVG dot tracks the page path. Its route passes offscreen through Selected Work and returns by Toolbox. The endpoint is a contact diagram rather than another navigation control.

**Cohesion.** The hero, Toolbox modules, and terminal share a recognizable signature. Four dark work figures use much the same dark framed silhouette, making different products feel visually alike. The flat vertical study index is useful but less distinctive. About is highly readable at display scale, yet its single-line credential and broadly worded biography make it less specific than the adjoining exhibits.

### Performance and platform details

- **Build and dependencies.** Next.js App Router 16.4.5, React/React DOM declared ^19.2.0, Node 24.x, Tailwind 4, local Geist, GSAP/ScrollTrigger 3.15.1, Lenis 1.3.27, and react-markdown 10.1.0. CSS 3D and SVG can still incur layout, paint, and compositing costs.
- **Network.** Homepage first view avoids the film. The film attaches on entry with `preload="auto"` after an initial `none` state, and the decoder seeks in 24fps increments without overlapping seeks. The first frame provides a compact fallback. The 2.26 MB desktop file and 0.87 MB compact file are the full asset sizes, not mandatory startup transfer. The CSS loading poster duplicates the same image URL rather than defining a second image. The Nudge source is served with responsive optimization. Current playback on slow mobile networks and high-frequency scroll input remains unmeasured.

These lab samples precede the latest local motion work. The release test observed roughly 381 kB total transfer for a cold mobile home run. - **Navigation and reading.** Skip link, semantic headings, native details, focus outlines, and case links support linear use. The sticky desktop rail, its separate progression coordinate, and easing can feel slower than ordinary document scrolling for users looking for one specific project. The old poster derivatives are deployable but absent from the current exhibit request path. No analytics integration or measurement dashboard was identified in this tree.
- **Coverage limits.** Current browser checks used Chromium on a workstation. Safari, current Firefox behavior, physical touch devices, slow cellular playback, video failure simulation, full no-JavaScript navigation, and current field performance were not rerun. Deployment history and earlier Firefox checks remain historical context.

## 11. Design weaknesses and risks

1. **Evidence arrives late.** The hero communicates craft, then four similar diagrams communicate categories. The first tangible application capture is Nudge. On a case study, the visitor reads several chapters before reaching the figure and source links.
2. **The film is compelling but semantically ambiguous.** The video depicts a media assembly and even contains a baked play triangle. That symbol looks interactive in the rendered frame, while the figure has no play control. The real admissions trace below is more relevant to the case study.
3. **Surface repetition limits project memory.** PGC-DHA, ResumeIQ, Ledger and Folio use similar green frames, panes, and typography, although their domains and interaction models differ.
4. **The narrative has weak personal anchors.** About is mostly a role label and broad experience summary. CS50x is buried. There is no approved portrait, direct inquiry route, project role detail, date, or human-scale result to balance the technical framing.
5. **Motion can compete with reading.** An edge exit works well during the rail, but the curve crosses copy on either side. The horizontal chapter gives an exhibit rhythm and requires a long vertical runway. The least comfortable experience is likely an input device or viewport near the pinning thresholds; the audit did not test physical devices there.
6. **Several documents lag implementation.** In addition to the old homepage order and social-card description, [CONTENT_VERIFICATION.md](CONTENT_VERIFICATION.md) describes earlier illustrative demos and pending toolbox examples. The current figures are titled Implementation diagram and unverified tool rows were removed. [TEST_PLAN.md](TEST_PLAN.md) still refers to the leading point staying at the same height during the rail, where the current design deliberately moves it offscreen.

## 13. Recommended future design direction

Treat the hero as the entrance to an exhibit whose displays are evidence. Keep the CSS assembly, dark canvas, mono annotations, and orange path. Use the next design pass to give each project one instantly recognizable artifact and one specific engineering decision. Put the CS50x credential close to the Academic entry with a verifiable artifact and a clear course-completion caption. Keep the UET degree visually distinct.

Prototype the gallery with its scroll-driven travel and a quick route to the case index. Use the full-motion view for browsing and a clear reading path for people who prefer less motion. Preserve the System film as an atmospheric introduction only if visitors can see how to control it and quickly reach the request trace. Measure the result on real input devices before adding new continuous motion.

The suggested order is evidence acquisition first, then one redesigned project and the credential, then propagation to the other studies. Ask the consultant to judge whether a visitor can identify the work, inspect proof, understand Sajid’s role, and find a way to make contact before assessing decorative motion.
